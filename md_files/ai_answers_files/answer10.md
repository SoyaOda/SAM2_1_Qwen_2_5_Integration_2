マスク位置ずれの原因とコード修正提案
画像・マスク前処理の一貫性チェック

現在のデータ前処理では、入力画像とマスクのリサイズ方法が一致していないことが確認できます。具体的には、セマンティックセグメンテーション用のSemSegDatasetで画像は アスペクト比を維持した上で長辺が所定サイズになるよう縮小し（既定ではQwen用に448ピクセル）
GitHub
、その後でSAM用に右端と下端に黒塗りパディングして1024×1024に拡張しています
GitHub
GitHub
。一方、マスクについては、HybridDataset内部でground_truth_maskを生成する際に、元マスクを直接モデル入力サイズ(1024×1024)にリサイズしています
GitHub
。この処理ではアスペクト比が考慮されず、縦横独立に圧縮・拡大されるため、元画像に対するマスク形状が歪む可能性があります。

例えば、元画像が縦長（高さ＞幅）の場合、画像は高さを1024に縮小し幅は比率に応じて縮小、残りを右側パディングしています。しかしマスクは幅方向も1024に拡大してしまうため、本来の物体の幅以上に引き伸ばされたマスクになってしまいます。同様に横長画像ではマスクが縦方向に過剰伸長されます。このように、画像とマスクの前処理に不整合があり、元画像座標系で見たときに両者の位置・形状がずれてしまうことが主な原因です。

モデル内部変換と解像度による位置ずれ

モデル内でも、SAMエンコーダに画像を入力する際に解像度変換とパディングが行われています。SAM2.1では画像特徴抽出時に入力画像を長辺1024にスケーリングし、足りない部分を右下にパディングする仕様です
GitHub
GitHub
。本プロジェクトでもpreprocess_sam_imageで同様の処理をしています。ところが前述の通り、データセット側で画像を448程度に縮小してから1024にパディングしており、SAMには低解像度化した画像が入力されています。この状態でSAMデコーダは内部で256×256の低解像度マスクを推論し、最終出力として1024×1024サイズにアップサンプリングします
GitHub
（SAM2.1では高解像度特徴が有効な場合、自身のconv_s0/s1で出力マスクを拡大）。一方でモデルは推論結果のマスクを元画像サイズに再マッピングしようとしています
GitHub
GitHub
。ここで、画像のパディング除去・スケーリング処理が厳密に一致していないと、マスクの位置がずれる恐れがあります。

実際、MinimalTrainerの可視化処理では、推論マスクに対しsam_postprocess_maskを適用してパディング部分を除去し元画像解像度にリサイズしています
GitHub
。この関数内では推論マスクを元画像の縦横サイズに合わせて拡大していますが、その前提となる「ResizeLongestSide後のサイズ」計算が、データセット側の画像縮小（448へのリサイズ）と齟齬を起こしている可能性があります。つまり、モデル内部で想定している画像のスケールと実際のGTマスクのスケールに食い違いがあり、マスク位置のずれにつながっていると考えられます。

Loss計算時のGTマスクと予測マスクの位置関係

訓練時の損失計算 (MinimalTrainer.compute_loss) を見ると、GTマスクと予測マスクのサイズ不一致が頻発するため、毎回GTマスクを予測マスクのサイズにリサイズして合わせています
GitHub
GitHub
。これは前述の前処理不整合によりGTと予測で解像度やアスペクト比が異なるためで、本来不要なはずのリサイズ処理が入っている状態です。

しかし、この対症療法的なリサイズでは既に歪んだGTマスクがさらに補正されるだけで、根本的な位置合わせは保証できません。例えばGTマスクが1024×1024に引き伸ばされていた場合、予測マスク（例：800×600相当）にNearest Neighborで縮小されます。このときマスクの重心や輪郭形状が微妙にずれ、Dice係数やBCEロスで見ても本来一致すべき箇所が不一致と判定されてしまいます。つまり、GTと予測の対応ピクセルがズレたまま損失が計算されている可能性が高く、学習に悪影響を与えていると考えられます。

正しくは画像と同じ変換をGTマスクにも適用し、モデル予測マスクとピクセルレベルで完全に重なるGTマスクを用意する必要があります。

可視化結果におけるオーバーレイ処理の確認

outputs/.../visualizationsに保存される画像を見ると、元画像に対するGTマスクと予測マスクの重なりにズレが確認できるはずです。可視化コード自体は、matplotlibで画像の上にマスクを透過表示しているだけで特別なオフセットは加えていません
GitHub
GitHub
。したがって、オーバーレイ時のズレはマスク側の前処理誤差に起因すると言えます。実際、可視化では予測マスクに対しsam_postprocess_maskでパディング除去・元サイズ復元を行い
GitHub
、GTマスクもcv2.resizeで元画像サイズに合わせています
GitHub
。それでもなお重ならない部分があるとすれば、GTマスク自体が元画像と厳密に合っていない（前述の歪みの影響）ことが原因です。オーバーレイ処理には追加の位置ずれ要因は無いので、可視化に現れるズレはそのまま前処理上の問題を反映しています。

主な原因の特定と修正方針

以上より、マスク位置ずれの主因はデータ前処理段階の不整合と断定できます。特に、画像とマスクのリサイズ・パディング処理が一致していない点（画像はアスペクト維持＋パディング、マスクはアスペクト非維持の直線形変換）が致命的です。

修正すべきポイント:

マスク前処理の改善: 画像に対して行っているのと同じ操作をGTマスクにも適用してください。具体的には、画像のリサイズ後サイズ(new_h, new_w)を算出したら、マスクもまずそのサイズにNearest Neighborでリサイズし、次に右下パディングでSAM_IMAGE_SIZE(1024)のキャンバスに配置します。こうすることで、マスクが画像とピクセル対応で重なるようになります。コード上は例えば以下のようになります（擬似コード）:

# 例: orig_h, orig_w が元画像サイズ
scale = target_size / max(orig_h, orig_w)
new_h = round(orig_h * scale)
new_w = round(orig_w * scale)
mask_resized = cv2.resize(mask_np, (new_w, new_h), interpolation=cv2.INTER_NEAREST)
padded = np.zeros((target_size, target_size), dtype=mask_resized.dtype)
padded[:new_h, :new_w] = mask_resized
ground_truth_mask = torch.from_numpy(padded).unsqueeze(0)  # (1, H, W) 形式


こうした処理により、例えば元が1200×800の画像ならマスクもまず1024×683に縮小してから残りをパディングし、画像_for_samと全く同じ1024×1024座標系でマスクを表現できます。現在はpreprocess_mask関数で一括リサイズしているためアスペクト比が崩れています
GitHub
。この関数を上記のように修正するか、新たにマスク用の処理を加えてください。

SAM画像リサイズの見直し: データセットでResizeLongestSide(448)を使用している箇所も検討が必要です。現状、画像は一旦448程度に縮小されており
GitHub
、その後1024に拡大（パディング）してSAMに渡しています。公式のSAMでは元画像の長辺を1024にするのが推奨であり、わざわざ低解像度に落としてからアップサンプルする現在の実装は精度面でもったいないです。幸いGTマスクも歪みなく1024フルサイズで用意できるようになるため、SemSegDatasetの初期化時にimage_sizeとしてsam_image_size(1024)を使うことを推奨します（HybridDataset内でSemSegDatasetを作る際にself.qwen_image_sizeではなくself.sam_image_sizeを渡す
GitHub
）。これにより、画像もマスクも可能な限り高精細なままSAMエンコーダに入力でき、位置合わせも単純になります。

モデル出力マスクの扱い: 上記修正により、GTマスクは常に1024×1024（パディング込み）のSAM座標系で管理できます。モデルの予測マスクも現在1024×1024で出ています（SAMデコーダ出力をアップサンプル後）
GitHub
ため、loss計算時に両者は同寸法のはずです。したがって、compute_loss内で行っているサイズ合わせ処理は不要となり、直接ピクセルごとのBCEやDiceが計算できます。もし動的解像度モードでimage_grid_thwに基づく出力リサイズを行っている場合は、訓練中はそれを固定1024に統一することも検討してください。モデルForwardでorig_h, orig_wを算出していますが、訓練時に限っては常にorig_h=orig_w=1024（SAM座標系）とみなしてしまい、GTマスクもそれに合わせる方法です。こうすれば常にpad込みの空間で比較することになり、パディング部分は両方0のため悪影響はありません。一方、推論時や評価時にはsam_postprocess_maskでパディング除去→元解像度に戻す処理をすればよく、用途に応じて使い分けられる構造になります。

検証: 修正後は、可視化オーバーレイ画像でGTマスクと予測マスクの輪郭が画像上でほぼ完全に一致することを確認してください。DiceスコアやIoUも向上するはずです。またcompute_loss内のログで、修正前は各バッチでpred_maskとgt_maskのshapeが異なっていたものが、一致する（リサイズ分岐に入らなくなる）ことを確認するとよいでしょう。

以上の修正により、画像とマスクの前処理からモデル出力まで一貫した座標系で扱えるようになります。公式実装や一般的なセマンティックセグメンテーションのベストプラクティス（例えば「マスクはNearestでリサイズ」「画像と同じ拡大縮小・パディングを適用」
GitHub
GitHub
）に沿った形でコードを改善することで、マスク位置ずれ問題は解消される見込みです。修正の際は既存のユーティリティ関数（例えばpreprocess_sam_image
GitHub
やsam_postprocess_mask
GitHub
のロジック）を再利用すると安全です。これらの対応により、追加のカスタム実装を最小限に抑えつつ、モデルの期待通りの振る舞いに近づけることができるでしょう。
