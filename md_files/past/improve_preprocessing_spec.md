データ前処理とマスク整合性の問題
背景と問題点

マルチモーダルモデルのセグメンテーション学習では、画像とマスクの前処理が一致していることが極めて重要です。不一致があるとモデルの予測と真値マスクが空間的にずれてしまい、損失が正しく計算されません。このプロジェクトでは各サンプルに画像・テキストプロンプト・真値マスクが含まれますが、以前は画像とマスクがランダムに対応付けが崩れるバグが存在しました。しかし、現在は「1会話につき1マスク」に修正され、画像とマスクのペアリング自体は正しくなっています（HybridDataset内で、マスクが存在すればセグメンテーションタスクとして扱う処理を実装
GitHub
GitHub
）。

しかし、前処理段階での画像とマスクの変換不一致という重大な問題が残っていました。具体的には、画像に適用したリサイズ・パディングと同じ操作をマスクに適用していないケースがあったのです。この結果、モデル入力時の画像座標系（例えば1024×1024の正方形）と、対応する真値マスクの座標系が食い違い、予測マスクと真値マスクがずれてしまっていました。

問題例

SemSegDataset（セマンティックセグメンテーション用）では、画像はQwenモデル用に縦横比保持リサイズ＋パディング（最大寸法を基準に448に縮小し14の倍数にパディング）し、SAMモデル用には1024×1024にリサイズ＋パディングする実装でした。一方でマスク（ラベル画像）は単純なリサイズのみでパディングしていない実装になっていました
GitHub
GitHub
。そのため、例えば元画像が長方形だった場合、画像は正方形にパディングされるのにマスクはパディングされず、位置がずれてしまいます。

ReasonSegDataset（画像中の特定記述に基づくセグメンテーション）でも、画像は1024×1024にパディングされるのに、マスク（JSONの多角形注釈から生成）を元の画像サイズのまま扱っていました。当初はこの不一致があり、モデル入力（1024）のマスクと元サイズのGTマスクが全く揃っていませんでした。

ReferSegDataset（参照対象のセグメンテーション）も同様で、画像を1024にリサイズ+パディングしている一方、取得したマスクは元画像解像度のままスタックしていました
GitHub
GitHub
。この場合、HybridDataset側でcoord_transformを使って元サイズ->1024への変換を後処理していますが、各データセット内で統一されていない点で不整合です。

以上のように、画像とマスクの座標系が一致しないために、損失計算時に常にマスクがずれ、高い損失が発生してモデルが正しく学習できない状態でした。「マスクと画像の位相がずれている」「予測マスクの有効領域が左上に偏る」といった開発メモも残っています（座標系の混乱）
GitHub
GitHub
。

修正方針: 画像・マスク前処理の統一

解決策はシンプルで、「画像に適用する変換をマスクにも寸分違わず**適用する」**ことです。具体的には:

アスペクト比を保持したリサイズを画像・マスク双方に実行し、

最終モデル入力サイズ（SAMの場合1024×1024）にパディングする処理を画像・マスク双方に適用する。

幸い、プロジェクト内にはSAM2.1モデル公式実装に基づいた変換ユーティリティが既に用意されています。src/transforms/geometry.pyで定義されている**SamSquareMetaクラスおよびapply_sam_transform_to_image・apply_sam_transform_to_mask関数です
GitHub
GitHub
。これらは「長辺をtarget_size(=1024)に揃え、右下余白をゼロ埋めして正方形にする」**SAM推奨の前処理を実装しています
GitHub
GitHub
。特にapply_sam_transform_to_maskは、画像変換時に得たメタデータ（リサイズ後サイズやパディング量を保持）を使い、**マスク画像に対して同じリサイズ・パディング（余白部分は指定値で塗り潰し）**を適用してくれます
GitHub
。

修正の基本方針は、各データセットの__getitem__内で:

画像を読み込む → 画像に対してSAM用の前処理（1024リサイズ+パディング）を実行し、同時に変換メタデータを取得する。

真値マスク（またはラベル）を取得する。

マスクにも上記メタデータを用いた同一変換を適用し、画像と同じ1024x1024座標系にマップする。

必要に応じて、マスクをモデル訓練用のテンソル（例えば1チャンネルの0/1マスクなど）に変換する。

以下、この方針を各データセットクラスに具体的に適用する修正プランを示します。

SemSegDatasetの場合

現行コードでは既に修正が適用済みです。SemSegDatasetでは、画像読み込み後に以下の処理を行っています（抜粋）:

# 画像のSAM用前処理（1024x1024）  
image_for_sam, sam_meta = apply_sam_transform_to_image(image)  
# ラベルも画像と同じ変換を適用  
label_for_sam = apply_sam_transform_to_mask(label, sam_meta, ignore_value=255)  
label = label_for_sam  # 以降、labelを置き換え  


上記の通り、apply_sam_transform_to_imageとapply_sam_transform_to_maskを対に使い、画像imageとラベルlabelに同じリサイズ・パディングを適用しています
GitHub
。ignore_value=255を指定することで、画像外のパディング部分はすべて255（無視ラベル）に塗られます
GitHub
。ADE20K等のセマンティックラベルでは255が無効値（IGNOREラベル）として使われているため、パディング領域は損失計算から除外され、モデルが余白で誤差を取られないようになります。結果、labelは1024×1024に拡張され、以降のクラスサンプリング・マスク生成処理では空間整合したマスクを用います
GitHub
GitHub
。SemSegDatasetは返り値としてマスク（単一クラスのバイナリマスク）とsam_metaを含む10要素タプルを返すようになっており、HybridDataset側でもorig_hwとして元画像サイズを保持しつつも、マスク自体は既にSAM座標系になっています
GitHub
。

まとめ: SemSegDatasetについては既に正しい実装（公式SAM2.1実装に準じた処理）が組み込まれているため、このまま維持します。修正コード例としては上記の通りですが、これは現コードに実装済みです
GitHub
。

ReasonSegDatasetの場合

ReasonSegDatasetでも、SemSegと同様に画像を1024正方に変換し、マスクも同じ変換を適用する必要があります。現時点で、ReasonSegDatasetには修正が部分的に導入済みです。「修正点」とコメントされた箇所で、以下のように実装されています
GitHub
:

# マスクをSAM画像と同じ変換で処理（修正点）
if mask is not None:
    # アスペクト比維持リサイズ
    mask_resized = cv2.resize(mask.astype(np.float32), (new_w, new_h), interpolation=cv2.INTER_NEAREST)
    # パディング（SAM画像と同じ）
    mask_padded = np.zeros((self.image_size, self.image_size), dtype=np.float32)
    mask_padded[:h, :w] = mask_resized
    mask = mask_padded


ここでnew_h, new_wおよびh, wは、直前に画像に対して行ったリサイズ後のサイズとパディング余白を表しています
GitHub
。このコードにより、マスク画像も画像と全く同じ縮尺・余白で1024×1024に正規化されます。ReasonSegではマスク値が1（対象領域）と255（無視領域、「ignore」フラグが付いた注釈）で構成されていますが、上記処理ではパディング部分を0で初期化しています
GitHub
。これは、パディング領域を「対象ではない背景=0」にみなす設計です。実際、この後の処理でsampled_masks = (mask == 1)と対象領域のみバイナリマスク化し、255だった無視領域も0（背景）扱いにしています
GitHub
。したがって、パディング部分は結果的に背景（値0）となり、損失には寄与しません。

以上の修正により、ReasonSegDatasetも画像・マスクが揃った1024×1024の座標系で出力を生成しています。実際に返り値では、masksテンソルはサイズ(1, 1024, 1024)でSAM入力座標系に整合済みであり
GitHub
、ラベルテンソルlabelはすべて255（IGNORE_INDEX）で埋められています
GitHub
（ReasonSegではマルチクラス分類を行わないため、ラベルマップはダミーとして全255にしています）。

さらなる改善: 現在のReasonSegDatasetの実装でも目的は達成されていますが、コードの一貫性という点では、SemSegDataset同様に**apply_sam_transform_to_imageとapply_sam_transform_to_mask関数を利用する**ことが望ましいです。例えば以下のように書き換えることができます:

image_for_sam, sam_meta = apply_sam_transform_to_image(image)
...
if mask is not None:
    mask = apply_sam_transform_to_mask(mask, sam_meta, ignore_value=0)


このようにすれば、リサイズ・パディング処理の重複実装を避け、公式実装に基づく信頼性の高い関数に任せることができます。ポイントはignore_valueの設定で、ReasonSegのマスクでは255を「無視」扱いしていましたが、パディング領域は背景として扱うためここでは0を指定します（つまり余白は何もない背景とみなす）。SemSegでは255を指定したのに対し、ReasonSegでは0を使う点に注意が必要です。この違いは、マスクの形式（後述）によります。

ReferSegDatasetの場合

ReferSegDatasetでは、現状まだマスクの前処理不一致の問題が残っています。コードを確認すると、画像に対してはSemSeg等と同様に1024にリサイズしパディングしています
GitHub
が、取得したマスクについては何も変換せずそのままテンソル化して返しています
GitHub
。例えば画像が640×480の場合、画像は1024×1024に拡大・パディングされますが、マスクは640×480のままスタックされており、HybridDataset内で後から変換している状態です。これを各データセット内で完結させるべく、ReferSegDatasetにも修正を加えます。

修正方法: 基本的にはSemSegDatasetと同様です。すなわち:

画像読み込み後、apply_sam_transform_to_imageでimage_for_samとsam_metaを得る（もしくは現行コードのようにcv2でリサイズ＋パディングしてもよいですが、メタデータ取得のため可能なら前者を推奨）。

マスク生成後（複数のCOCOアノテーションをデコードしmasksリストに格納した後）、各マスクに対し**apply_sam_transform_to_mask(mask, sam_meta, ignore_value=0)**を適用する。

ReferSegのマスクは各対象物の領域を示すバイナリマスク（背景0、対象領域1）です。パディング領域は対象外の背景として扱うので、ignore_value=0でパディングします（ReasonSegと同様の理由）。

masksリスト内の各m（NumPy配列）に関数を適用し、返ってきた1024×1024マスクを収集します。複数ある場合はそれらをスタックしてテンソル化します（ただし基本設定ではnum_classes_per_sample=1のため1つだけになる想定）。

返り値のmasks項目には変換後のマスクテンソルを入れます。また、セマンティックラベルlabelは現在ダミーで全255を入れていますが、パディング後もそれで問題ありません（全255のまま1024×1024にするか、あるいはapply_sam_transform_to_maskで255塗りつぶししても結果は同じ全255になります）。

コード例（擬似コード）は以下のようになります（公式Transform利用版）:

image = cv2.imread(image_path)[:, :, ::-1]  # BGR→RGB
image_for_sam, sam_meta = apply_sam_transform_to_image(image)
...  # Qwen用前処理等
masks = [] 
for ann_id in sampled_ann_ids:
    m = decode_mask_from_ann(ann_id)  # 元画像サイズでのマスク取得 (np.ndarray)
    m_sam = apply_sam_transform_to_mask(m, sam_meta, ignore_value=0)
    masks.append(m_sam)
masks = np.stack(masks, axis=0)
masks = torch.from_numpy(masks).float()


上記のdecode_mask_from_annは、現行コードで行っているCOCO注釈からマスク配列を得る処理（mask.decode(rle)等）の部分に相当します。また、apply_sam_transform_to_maskの戻りはNumPy配列なので、まとめてスタック後にテンソル化しています。

ReferSegDatasetにこの修正を加えることで、画像とマスクが共に1024×1024の座標系に統一されます。HybridDataset内で現在行っているマスクの追加変換処理（preprocess_mask_with_aspect_ratioを使った補正
GitHub
GitHub
）は基本的に不要となります。実際、HybridDatasetのコードでは、サンプルから得たground_truth_maskサイズがSAM入力サイズと異なる場合に補正するロジックがあります
GitHub
。修正後はSemSeg・ReasonSeg・ReferSegいずれのデータセットも常に1024サイズのマスクを返すようになるため、この条件分岐は原則真にならず、冗長な再リサイズは発生しません。結果的に学習時の損失計算が簡潔になり、無駄な補正による副作用も避けられます。

HybridDataset側の対応

上記のように各データセットが修正されれば、HybridDataset側では特別な対応は不要です。selected_dataset[sample_idx]で取得したデータが既に整合済みマスクを持っているため、HybridDatasetはそれをそのまま使用して損失を計算できます。is_seg_sampleの判定やSEGトークンの挿入処理はそのままで問題ありません
GitHub
GitHub
。強いて言えば、前述の追加リサイズ処理（preprocess_mask_with_aspect_ratioを呼ぶ箇所）は整理可能ですが、実装上すぐ支障が出るものではないので、後でクリーンアップすれば良いでしょう。

マスク形式と解像度の一貫性

マスク形式について整理すると、本プロジェクトではケースにより以下の2種類があります:

バイナリマスク（0-1）: ReasonSegDatasetやReferSegDatasetでは、対象領域を1、背景を0とした単一対象のマスクを扱います（ReasonSegではさらに「ignore」領域として255を用いる場合あり
GitHub
）。学習時には1チャンネルのバイナリマスクとしてモデルに入力し、予測もバイナリ（背景vs対象）で行います。

セマンティックマスク（多クラス）: SemSegDatasetではデータセットごとのラベルIDを持つマスク（例: ADE20Kではカテゴリごとに0～149のID、背景や未定義を255）を読み込みます
GitHub
。ただし、この実装では1サンプルにつき1クラスのマスクに統一するため、読み込んだラベルマップからランダムに1クラスを選び出し、そのクラスの領域のみを1、他は0とするバイナリマスクを生成しています
GitHub
GitHub
。従って、モデルに渡すときは結局バイナリマスクです。元の多クラス情報はlabel_tensorとして保持されますが、損失計算では使われません。

重要なのは、いずれの形式でもモデル入出力時点ではマスクは画像と同じ解像度・サイズであるべきという点です。今回の修正で目指すのは、このサイズを統一して1024×1024（SAMモデルの入力解像度）にすることです。すでに修正済みのSemSeg/ReasonSegでは、出力するmasksテンソルがしっかり1024×1024になっていることを確認できます（SemSeg:
GitHub
、ReasonSeg:
GitHub
）。ReferSegも上記修正により同様にします。

一方で、Qwen2.5-VLエンコーダ側の画像解像度（通常は448×448）とは一致しない点に注意してください。Dual-Encoderモデルの特殊性として、テキスト生成はQwenの視覚特徴（448サイズ）を使い、セグメンテーションはSAMの視覚特徴（1024サイズ）を使うという構造になっています。そのため、マスクはあくまでSAM側の出力空間（1024）で定義されます。Qwen側の448解像度はセグメンテーションマスクには直接関与しません（予測マスクをどの座標系で生成するかという議題がありますが、基本方針はSAM座標系でマスクを生成し、それを元画像座標系に戻す流れです
GitHub
GitHub
）。従って、真値マスクは常に1024×1024で用意し、モデル内部でも予測マスクを1024にアップサンプルしてから損失を計算する、という手順になります
GitHub
GitHub
。

最後に公式実装との整合について触れます。今回導入する処理は、Meta社のSAM (Segment Anything)公式実装に準拠したものですし、Qwen2.5-VLの画像前処理も公式の値を用いています（例えばQwen画像正規化の平均・標準偏差は公式と同じ値
GitHub
を使用）。Huggingface版のQwen2.5-VL AutoProcessorも内部で似た処理を行いますが、本プロジェクトではカスタムデータセット内で実装しているため、公式手順を踏襲しつつも統一されたインターフェースで処理しています。今後、前処理部分をHuggingfaceの実装に置き換えることも可能ですが、現状のコードベースでは既に公式に忠実な処理となっているので、この方針で問題ありません。

結論

提案した修正プランに沿ってSemSegDataset・ReasonSegDataset・ReferSegDatasetすべてで画像とマスクの前処理を統一すれば、セグメンテーションタスクにおける座標系の不整合は解消されます。モデルは正しい対応関係の入力で学習できるため、無駄な損失に悩まされることなく真に対象領域を学習できます。また、この統一によりHybridDataset側の余分なマスク補正処理も不要となり、コードの見通しも良くなります。公式実装（Qwen2.5-VL・SAM2.1）の知見を取り入れた形で安全に修正できるため、ぜひ早急に適用すべきです。修正後は、マスクロジットとGTマスクがピクセルレベルで正しく整合し、安定したセグメンテーション学習と精度向上が期待できます。
