# 問題1: テキスト指示の空間情報不足と修正策

**問題点:** 現在、本モデルではセグメンテーション指示に対し、SAMのプロンプトエンコーダに常に画像中心のポイントを与えています。そして得られたポイント埋め込みをテキスト由来の埋め込みに差し替えているため、実質的に**オブジェクトの位置手掛かりが失われている**状態です。その結果、対象物が中央になければマスクDecoderは誤った領域を切り取ろうとし、学習初期には常に中心付近の不正確なマスクが出力されてseg\_lossが高止まりする一因となっていました。

**修正方針:** **擬似ポイントを動的に配置**し、テキスト指示に空間的ヒントを与えます。具体的には、**真値マスクの位置に基づいてポイント座標を決定**します。最も単純な方法は\*\*マスクの重心（センロイド）\*\*を計算し、その座標をプロンプトエンコーダに入力することです（あるいはバウンディングボックスの中心でも概ね同等です）。この修正により、各訓練サンプルごとに対象物の概略位置をモデルに提供でき、画像中央への固定バイアスを解消できます。

* **実装手順:** モデルのforward処理内で、ラベルマスク（`mask_labels`）から対象領域の中心座標を算出し、これをSAMプロンプトエンコーダへの入力ポイントに用います。例えば、現在は以下のように画像中心を計算しています:

  ```python
  h_feat, w_feat = image_features_sam[i:i+1].shape[-2:]
  h_img, w_img = h_feat * 16, w_feat * 16
  center_x, center_y = w_img // 2, h_img // 2
  point_coords = torch.tensor([[center_x, center_y]], ...)
  ```

  ここを、**真値マスクの重心座標 `(cx, cy)`** に置き換えます（必要に応じて元画像座標からモデル内部座標系への変換が必要です）。例えば、各バッチで利用可能な`mask_labels[i]`から非ゼロ画素の平均位置を計算し、その値を16倍して（特徴マップから元画像へのスケール）`point_coords`に設定します。

  > 📌 *補足:* `src.utils.coordinate_transform.py`等のユーティリティがある場合、それを用いて元画像→モデル入力間の座標変換を正確に行ってください。例えば画像を1024×1024にパディングしているなら、重心座標にも同様のパディングオフセットとスケーリングを適用する必要があります。

* **ポイント埋め込みの扱い:** テキスト由来の埋め込みとポイント埋め込みの融合も検討します。現在はポイントの*sparse*埋め込みを **丸ごとテキスト埋め込みに差し替え** ています。これではポイントの持つ位置情報が完全に失われるため、位置特定が難しくなっていました。修正後も単純に置き換える場合、今度は重心に配置したポイントなので改善しますが、**ベストプラクティス**としては*テキスト埋め込みと位置埋め込みの情報を組み合わせる*方法が考えられます。例えば「ポイント埋め込みの一部にテキスト特徴を加算する」「ポイントを複数与えてテキスト埋め込みも別途一つのポイント扱いにする」等です。しかし大きな改変になるため、まずは**重心ポイント + テキスト埋め込み置換**でシンプルに実装し、効果を見るのが良いでしょう。

* **複数インスタンスへの対応:** セマンティックセグメンテーションでは、1クラスに複数インスタンスが存在する場合があります。この場合、単一のポイントではマスクDecoderが画像内の一部しか捉えず、真値マスク（複数領域の合成）を十分にカバーできない恐れがあります。可能な改善策として、**複数ポイントのプロンプト入力**があります。すなわち、真値マスクの連結成分ごとに代表点を選び、例えば最大で2～3点程度のpositiveポイントをSAMに与える方法です。SAMのPromptEncoderは複数ポイントも受け付けるため、それら全てに対して特徴抽出し、そのうち1つ（例: 最初のポイント）の埋め込みにテキストベクトルを注入し、残りはそのまま位置アンカーとして活かす設計が考えられます。これにより、モデルは**テキスト＋複数座標**の複合プロンプトから複数離れた領域を包括するマスクを出力しやすくなります。ただし、この改修は実装複雑度が増すため、まずは\*\*各サンプル1ポイント（重心）\*\*で試し、必要に応じて拡張する段階的アプローチが望ましいです。

* **マスクサイズの整合:** 併せて、**真値マスクの前処理**にも注意が必要です。現在、モデル出力マスクは動的解像度により**入力画像と同じサイズ**（パディング後含む）にリサイズされています。一方、データセットから読み込む`mask_labels`は元画像サイズであり、パディングやリサイズを反映していません。そのままでは**予測マスクとGTマスクのサイズ不整合**が生じ、損失計算に誤差を導入します。対策として、**GTマスクにもモデル入力と同じリサイズ・パディング**を適用しましょう。例えば画像を448→14の倍数にパディングした場合はマスクにも同じだけ余白を追加し、1024×1024に拡大した場合も同様にリサイズします。もしくは、予測マスクを元のマスクサイズにクロップして比較する方法でも構いません。重要なのは、**mask\_logitsとmask\_labelsのテンソル形状を一致**させ、対応する画素が正しく比較されるようにすることです。これにより、境界部のパディング領域などで不必要な損失が発生するのを防ぎます。

以上の修正により、テキストだけでは補えなかった\*\*「どこにあるか」\*\*の情報をモデルに与え、seg\_lossの改善が期待できます。

# 問題2: マルチマスク出力の複雑さと修正策

**問題点:** 現行設計では、1つの会話（QAペア）中に複数の`<SEG>`トークンを出力させることで**複数マスク**に対応しようとしていました。例えば「人と犬をセグメントして」といった指示に対し、モデルは`<SEG><SEG>`の2トークンを生成し、それぞれ別個のマスクを出力する想定です。しかし、この形式はLLMにとって**出力制御が非常に難しい**上、データセット側でも明示的にマルチマスクの指示は用意されていないため、実質的に訓練で学習できていません（現状のコード実装上は複数`<SEG>`トークンに対応可能ですが、トレーニングデータ中にほぼ存在しない）。その結果、**seg\_lossが下がらない**ケース（複数対象を1枚のマスクにまとめてしまい誤差が残る等）が発生し得ます。

**修正方針:** **1会話につき1マスク出力**に統一するのが最新のベストプラクティスです。つまり、**マルチクラスの同時セグメンテーション要求は訓練データ上作らない**方針です。一枚の画像に複数対象がある場合でも、それぞれを別個のQAペア（または別ターン）として扱います。この戦略は、LISAモデルの設計にも沿っています。実際、LISAの学習データでは**セマンティックセグメンテーションのマルチクラス注釈をクラスごとの個別質問に変換**しています（例：「画像中の`{class_name}`をセグメントして下さい。」→答えはそれぞれ`<SEG>`） 。RefCOCO等の参照型セグメンテーションも1指示1対象が基本です。したがって、本プロジェクトでも**各データセットサンプルが一つのマスクのみを含むように設計を簡素化**すべきです。

* **セマンティックセグメンテーションデータ:** 現在、ADE20KやCOCO-Stuffなどでは1画像に複数クラスの物体が含まれますが、訓練データ作成時にこれらを**クラス単位に分割**する必要があります。コード上では、`SemSegDataset`内で各画像のアノテーションからユニークなクラスIDを集め、`num_classes_per_sample`枚だけランダムに選んで複数のQAペアを生成していました（デフォルトでは最大3クラスを選択） 。このアプローチを改め、\*\*`num_classes_per_sample = 1`\*\*と設定するか、あるいはクラスごとにサンプルを別エントリとして返すよう変更します。例えば、`sampled_classes`の選択を1件のみにし、`conversations`リストにも1ペアのQAだけを含む形に簡素化します。こうすることで、各呼び出しでモデルが生成すべきマスクは常に一つとなり、LLMの出力制御負荷も大幅に軽減されます。

* **データローダと損失計算:** 上記変更後は、`mask_logits`および`mask_labels`も各サンプルにつきリストではなく単一マスクになります（現在の実装では`mask_logits_list`にサブリストとして複数マスクを保持し、ループで損失計算していました）。シンプルに1サンプル1マスクであれば、これらをテンソルに統合して損失計算でき、実装も明快になります。もし既存コードを大きく変えずに対応するなら、`num_classes_per_sample=1`に設定するだけで内部的には各サンプルのマスクリスト長が1になり、複数マスクループの影響は無くなるため実質的に同等です。

* **マルチターンの拡張:** 将来的にユーザから「画像中の人と犬を両方セグメントして」といった複数対象指示がある場合は、**モデル内で自動的に質問を分割する**方法も考えられます。例えば、一つのプロンプトに対し内部で人用と犬用の2回の推論を行い、それぞれマスクを返す仕組みです。ただ、これも推論時の工夫であり、**学習時にはシンプルに一対一対応で十分**です。LISA論文でも、暗黙的に複数対象を含む高度な指示（ReasonSeg）の学習は行っておらず、まずは単一対象の明示的指示データでモデルを鍛えています。

* **各タスクへの適用:** セマンティックセグメンテーション以外のタスクは元々1指示1対象です。Refer Segmentation（RefCOCO系列）は各参照表現に対し単一の対象物マスクが付与されています。Visual QAデータはセグメント出力を伴わない質問応答ペアです。Reasoning Segmentation（ReasonSeg）は画像＋暗黙的指示に対しターゲット一領域のマスクを返すタスクで、こちらも一度に一領域のみです。したがって、セマンティック系データの処理を上記方針に揃えれば、**全タスクで一貫して1質問→1マスク**となります。

* **データ前処理の細部確認:** ハイブリッドデータセット構築において、変換形式を再点検します。すでに実装上、`SemSegDataset`ではメッセージ形式のQAペア列を生成し、マスクもクラスごとに抽出しています。今後は各画像についてループを回さず単一の質問を返すようにすれば、下位互換を保ちつつ設計を簡素化できます。またIssue #1で述べたように、マスクと画像のサイズ合わせ（パディング含む）を徹底することも重要です。加えて、特殊トークン`<SEG>`の扱い統一やメッセージ形式への統合は既に対応済みですが、引き続き**一貫性の検証**を行います。例えば、`[SEG]`表記のデータが残っていないか、`messages`リストが正しいRole順序で構成されているか（システムプロンプト→ユーザ→アシスタント）などを確認します。これら前処理が正しく整備されていれば、学習データの品質が向上し、モデルも意図したとおり**1質問に正確な1マスク**を出力できるようになるでしょう。

以上の修正指針により、モデル設計とデータセット構成の不整合を解消し、無駄な誤差要因を取り除くことができます。実装は多少複雑になりますが、\*\*「テキスト＋位置プロンプトで1対象をセグメントする」\*\*という本来のタスクに沿ったシンプルな枠組みにモデルを合わせ込むことで、SEG損失の停滞打破と性能向上が期待できます。
