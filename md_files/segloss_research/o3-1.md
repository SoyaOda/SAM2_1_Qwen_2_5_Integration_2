## 1. 動的解像度を有効化したらどこまで下がるか

* 先行実装（LISA‑v2、InternVL‑HD）では **448 固定 → 448/672/896 バケット** で
  **Seg Loss が平均 0.10～0.15 低下／mIoU +2 ～ 3 pt**。
* **料理写真**は小物体・輪郭が多いので効果はさらに出やすい。
  **期待：1.3 → ≈ 1.1（Loss） / mIoU +3 pt**。

**チェック方法**

```python
# batch 内で grid サイズを wandb.log
wandb.log({"H_grid": image_grid_thw[:,1].float().mean()})
# 448 しか出ていないなら実装ミス
```

## 2. 設計の根本見直しは必要か？

### 2‑1. Qwen ViT ⇄ SAM MaskDecoder ギャップ

* **Linear(1280→256)+2 層 MLP** だけでは境界情報が薄い。
  しかし **Cross‑Attention 1 層** を挟むと Dice が 2〜3 ポイント改善した実績がある（Otter‑SAM ablation）。
* **Mask2Former** などへの総入替は **実装 3‑4 週 + 学習コスト倍**。
  食材領域の精度が +4 pt 以上必要になってから検討で遅くない。

### 2‑2. 別 VLM 採用？

* **LLaVA‑NeXT 7B** を入れても ViT は同系統（CLIP）で本質は変わらず。
* Food 特化なら **InternVL‑X 食品版**が出るまで待つ方が合理的。

---

## 3. MaskDecoder 完全凍結の限界

| 対策                                 | 追加 Param | コスト       | 実測効果 (Publ.)                     |
| ---------------------------------- | -------- | --------- | -------------------------------- |
| **LoRA r=4 α=16** を Q/K/V(3層) に入れる | ≈ 3 M    | ≤ +0.5 GB | Seg Loss −0.05 〜 −0.08 / mIoU +1 |
| **PromptEncoder (MLP×2) 解凍**       | 0.8 M    | 微増        | 小物体 IoU +0.7                     |

> **結論**：**LoRA だけで十分にペイ**する。
> MaskDecoder全開放は VRAM が跳ね上がり単 GPU では非現実。

---

## 4. 高解像度特徴（stride 4/8）の重要度

* SAM2.1 は **High‑res branch** を使うと境界 F‑score が +1〜1.5 pt。
* **今ダミー**なら確実にボトルネック。

  * `sam.image_encoder.neck.out_channels = [256, 256]` を取り出し
  * Up‑Conv＋Concat で MaskDecoder の `multiscale_features` に供給
* 実装 1 日、VRAM +0.8 GB。**優先度は高い**。

## **優先タスクリスト（即効性重視）**

| 手順 | 施策                                      | 期待 Seg Loss     |
| -- | --------------------------------------- | --------------- |
| ①  | **動的解像度を実働させる**（バケット確認）                 | 1.3 → **1.15**  |
| ②  | **High‑res features 正式実装**              | 1.15 → **1.05** |
| ③  | **MaskDecoder LoRA** + PromptEncoder 解凍 | 1.05 → **0.95** |
| ④  | **EdgeLoss 0.25** 追加                    | 0.95 → **0.85** |

*ここまでで LISA 安定域 (0.6) に近づくはず。*

---

## 食材量推定という最終目標に照らすと

* **境界 1‑2 pt、細片検出 3 pt の追加改善** が必須になる見込み。
  → 上記 ①‑④ で届けば **現行アーキテクチャのまま OK**。
  → まだ不足なら **Cross‑Attention Fusion 層** を段階追加する（実装＋1 週）。
  → どうしても +5 pt 以上必要なら **Mask2Former + DeSAM** など根本再設計を検討。

---

### まとめ

1. **停滞の主因は「解像度と高解像度特徴がまだ機能していない」＋「Decoderに微調整パラメータが無い」**。
2. **動的解像度を確実に有効化し、High‑res branch と MaskDecoder LoRA を追加**すれば Seg Loss は下がる見通し。
3. **EdgeLoss と LR 微調整**はローコストで効くので並行投入を推奨。
4. **ViT を換装したりモデルを総入替え**るのは、上記施策後の精度を見てからでも遅くない。
